
__Пример:__ <br>
Тестирование нового мобильного банковского приложения. На данный момент готовы:

- Отдельный модуль для перевода средств между счетами(без подключения к реальному банковскому шлюзу).
- Макет интерфейса с основными экранами.
- Первая полная сборка приложения для внутренних сотрудников. 

| По стадии проведения процесса тестирования | По знанию устройства системы | По направленности тестового сценария | По выполнению кода |
|:-------------------------------------------|:-----------------------------|:-------------------------------------|:-------------------|
| *Alfa-тестирование*: тестирование макета интерфейса (п.2) силами дизайнеров и продукт-менеджеров на удобство и логику переходов. | *Black-Box:* проверка выполнения стандартного перевода средств между счетами, отображения баланса, получения уведомления об успешной операции. | *Функциональное тестирование:* проверка переводов денежных средств между тестовыми пользователями. | *Статическое тестирование:* проверка кода верстки страницы, что стилизация соответствует требованиям.|
| *Бета-тестирование*: проверяется корректность первой полной сборки приложения на устройствах сотрудников, которые не участвовали в разработке.|*Gray-Box:* проверка состояния базы данных после регистрации пользователя в системе банка. | *Smoke-тестирование:* проверка что основные функции (вход в банк, перевод средств, просмотр баланса) работают корректно.| *Динамическое тестирование:* запуск автоматических тестов, которые проверяют разные значения перевода денежных средств, корректность обработки кодом таких переводов. |
| *Системное тестирование*: проверяется работа приложения на соответствие всем функциональным требованиям(такие как переводы / история / настройка). | *White-Box:* проверка корректности работы перевода больших денежных средств(зная лимит), проверка транзакций в бд.| *Регрессионное тестирование:* проверка функциональности новой сборки после исправления прошлых багов. | |
